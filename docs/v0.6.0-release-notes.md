# v0.6.0 — Phase 6 broker kernel and unified handovers

Release candidate — not yet published.

Phase 6 brings the GitHub, handover, egress, and Family brokers onto a shared
kernel for framing, capability validation, private runtime artifacts, peer
admission, audit, and lifecycle management. Protocol compatibility and the
intentional stage 2 behavior changes are recorded in the
[stage 2 design](superpowers/specs/2026-09-06-broker-kernel-stage2-design.md).

- Codex and Claude now create handovers through the same create-only broker.
  Saved handovers are mounted read-only; broker failure does not fall back to
  direct writes. Canonical Session remains unrecorded, while an agent-reported
  conversation ID may be included in the body as unverified by the host.
- Egress sequence handling is corrected so an earlier denied or reordered
  request does not invalidate all later requests. Runtime cleanup and worker
  lifecycle fixes are included.
- Managed Claude statusline and workspace trust seeding, host Codex handover
  discovery, and jq in the agent image are included.

## Updating existing projects

Codex requires managed profile version 5. Rebuild the agent image, stop the
project's sessions, and follow the [existing project update procedure](codex-operations.md#既存projectの更新),
including `agentctl project update-profile PROJECT` and doctor checks.
If the handover root overlaps private state or a writable mount, move it using
the documented operator procedure before starting a new runtime. Existing
documents are not moved automatically. The new setup default places handovers
beside private state.

## Sandbox changes since v0.5.0

- Agent runtime containers unmask `/proc/*` to let nested sandboxes mount proc.
  Some proc entries become readable; writes to `/proc/sys` rely on non-root
  ownership and dropped capabilities instead of the earlier read-only mounts.
- Claude uses the strong nested sandbox with subprocess credential environment
  scrubbing. Workspace trust seeding also enables project permission allow rules
  and additional directories, as accepting workspace trust does.
- Codex workspace-write tools now have the same network reachability as their
  container. Domain restrictions require the project's egress policy; projects
  without that policy still have unrestricted outbound networking.

These changes retain managed deny rules and broker authorization. See the
[changelog](../CHANGELOG.md) for the detailed boundaries. The existing 0.x
CLI/state compatibility caveats apply.

## Validation

Candidate results and the exact reviewed commit are maintained in the
[release record](v0.6.0-release.md). Required CI includes Unit tests and all
17 real Podman integration tests without skips.

Authenticated host evidence is the September 7 Phase 6 S2-4 and Issue #120
verification. Issue #120 used non-interactive Codex / Claude CLI tools in their
normal sandboxes; interactive TUI operation and actual conversation ID capture
were not tested. Fresh candidate authenticated host smoke and existing project
migration have not been run. The earlier CI TLS timeout / Family PID failure
remains unexplained despite later passing runs.

Candidate `0119a8a` CI attempt 1 also failed: the local TLS fixture timed out,
Family runtime PID acquisition failed, and two injected registration-failure
cases reported cleanup errors. In those two cases the later container-absence
assertions were not reached, so cleanup was not verified. The logs do not
establish whether containers remained or had already been removed. A passing
rerun does not resolve this cause; candidate attempts and the final gate result
are recorded in [PR #126](https://github.com/jj1xgo/agent-container/pull/126).

## Install after publication

`git clone --branch v0.6.0 --depth 1 https://github.com/jj1xgo/agent-container.git`

A clean release-tag checkout will report `agentctl 0.6.0`. Until publication,
the latest stable release remains v0.5.0. Phase 7 Vault config sync is not
included in this release.
