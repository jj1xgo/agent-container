# v0.6.0 Release Preparation Plan

**Goal:** Phase 6 と Issue #120 を含む main を、公開判断できる v0.6.0 候補へ整える。

**Architecture:** 基準は main `476304bf76153ffade23458d2100c13ed30e3973`。runtime を変更せず、release metadata と既存の version/docs contract を更新する。候補はタグが付くまで `0.6.0-dev`、公開済み stable の案内は `v0.5.0` を維持する。

**Tech Stack:** Python unittest、Git annotated tag、GitHub PR / CI / Release。

**Spec:** [release record](../../v0.6.0-release.md)、[roadmap 更新規則](../../development-roadmap.md#更新規則)。

## Constraints

- 実装基準と履歴の認証済み smoke、新規候補の自動検証を区別する。
- 既存 tag、元 workspace、登録済み project と保存文書を変更しない。
- 公開前に exact candidate、notes、CI、未実施項目を提示する。
- commit には `Co-authored-by: Codex <codex@openai.com>` を付ける。

## Publication follow-up

公開操作の判断後、承認された候補へ immutable annotated tag を作成・push し、tag の peeled SHA を確認して GitHub Release を作成・再照会する。未公開の tag を latest stable と案内しない。公開後の別変更で README の stable を `v0.6.0`、main の開発系列を `0.7.0-dev`（base `v0.6.0`）へ更新し、CHANGELOG の公開日と roadmap の結果を記録する。Phase 7 実装はこの判断の後に扱う。
